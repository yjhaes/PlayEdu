# Redis 分布式学习状态与实时学习榜

Status: ready-for-agent

## Problem Statement

PlayEdu 当前使用进程内 Map 保存缓存、锁、限流计数和学习心跳状态。这些状态在多实例之间不共享，现有锁的读取与写入也不是原子操作，可能造成限流被绕过、学习进度重复写入、学习时长计算异常和 LDAP 并发登录重复处理。每日学习榜每次直接查询 MySQL；每日学习时长采用“先查询再更新”，且缺少用户与日期的唯一约束，并发时可能丢失增量或产生重复记录。

项目需要一条适合简历展示、能够通过真实并发测试证明的 Redis 改造闭环：Redis 作为强制依赖承担跨实例协调与实时查询投影，MySQL 继续保存权威学习数据。

## Solution

引入 Spring Data Redis 和 Redisson，删除进程内缓存、锁和限流实现。使用 Redisson 实现分布式锁和请求令牌桶，使用 Redis Lua 原子管理登录失败计数与活跃学习租约，使用 Redis ZSet 提供今天和昨天的实时学习榜。

同一学员同时只能有一个活跃学习课时。第一次学习心跳只建立租约，从第二次连续有效心跳开始累计时长；发生多课时冲突时向客户端返回明确业务结果。MySQL 在一个事务中保存课时进度、课程进度和每日学习时长，事务提交后异步更新 Redis 排行榜。排行榜不是权威数据，Redis 数据丢失后从 MySQL 重建。

## User Stories

1. As a 学员, I want 我的学习进度在请求被不同 API 实例处理时仍然正确, so that 扩容不会导致学习记录重复或丢失。
2. As a 学员, I want 第一次学习心跳只建立学习租约, so that 单次伪造请求不能凭空获得学习时长。
3. As a 学员, I want 后续连续有效的学习心跳累计实际学习区间, so that 我的学习时长能够稳定增长。
4. As a 学员, I want 暂停、结束或切换课时时主动结束当前学习租约, so that 我可以及时开始学习另一个课时。
5. As a 学员, I want 浏览器异常退出后学习租约自动过期, so that 我不会永久无法开始另一个课时。
6. As a 学员, I want 多个标签页同时播放时只有一个课时被计时, so that 学习时长不会被重复累计。
7. As a 学员, I want 第二个课时发生学习冲突时得到明确提示, so that 我知道为什么该视频没有累计学习时长。
8. As a 学员, I want 短暂网络抖动不会被计算为一段很长的连续学习, so that 学习统计保持可信。
9. As a 学员, I want 重复或乱序的心跳不会重复增加学习时长, so that 客户端重试不会污染记录。
10. As a 学员, I want Redis 临时故障时收到可重试的明确错误, so that 系统不会假装成功但丢失学习状态。
11. As a 学员, I want 课程观看权限直接依据权威数据判断, so that 权限新增或撤销后不会继续受到陈旧缓存影响。
12. As a 管理员, I want Dashboard 快速展示今天的学习时长 Top 10, so that 我能及时了解当天学习活跃度。
13. As a 管理员, I want Dashboard 展示昨天的学习时长 Top 10, so that 我能对比近期学习情况。
14. As a 管理员, I want 学习榜在 Redis 清空或重启后能够从 MySQL 重建, so that 临时投影丢失不会损坏权威数据。
15. As a 管理员, I want 通过受权限保护的业务操作重建学习榜, so that 我无需访问通用缓存管理接口。
16. As a 管理员, I want 排行榜异步更新失败时不回滚已经提交的学习记录, so that 展示故障不会破坏学习事实。
17. As a 安全管理员, I want API 请求配额在所有实例之间共享, so that 客户端不能通过负载均衡绕过限流。
18. As a 安全管理员, I want 学员登录失败次数在所有实例之间共享, so that 暴力尝试不能通过切换节点绕过锁定。
19. As a 安全管理员, I want 管理员登录失败次数在所有实例之间共享, so that 后台账号受到一致保护。
20. As a 用户, I want 登录成功后相应的失败计数被清除, so that 之前的偶发输入错误不会继续影响正常登录。
21. As a 用户, I want 达到锁定阈值后的剩余等待时间准确显示, so that 我知道何时可以再次尝试。
22. As a 运维人员, I want Redis 不可用时应用启动失败并暴露不健康状态, so that 不完整实例不会接收流量。
23. As a 运维人员, I want 锁、限流和学习租约在 Redis 运行时故障时明确失败, so that 系统不会静默退化为错误的单机语义。
24. As a 运维人员, I want 排行榜更新失败留下结构化日志和指标, so that 我能发现并触发重建。
25. As a 运维人员, I want Redis 中的数据按 PlayEdu 命名空间组织, so that 应用状态不会与其他系统的 key 冲突。
26. As a 开发者, I want 分布式锁的获取、执行和释放由一个模块管理, so that 调用者不会遗漏释放或采用不同错误策略。
27. As a 开发者, I want 请求限流与登录失败跟踪使用不同的业务接口, so that 两种不同语义不会被一个含糊计数接口耦合。
28. As a 开发者, I want 使用真实 Redis 运行集成测试, so that Lua、TTL、Redisson 锁和 ZSet 行为不是由 Mock 猜测。
29. As a 面试展示者, I want 用两个 API 实例复现改造前后的并发差异, so that Redis 带来的跨实例正确性可以被直接证明。
30. As a 面试展示者, I want 保留压测结果、架构决策和故障说明, so that 项目改造的取舍能够被清楚讲解。

## Implementation Decisions

- Redis 是应用的强制依赖，不提供内存模式，也不在运行时自动回退到进程内实现。
- 开发和演示环境支持外部 Redis（例如 WSL 中独立运行的 Redis）或可选的 Docker Compose 单节点 Redis。Redis 连接参数通过外部配置提供；连接在启动阶段不可用时应用启动失败。
- 使用 Spring Data Redis 执行显式字符串序列化、Lua 脚本和 ZSet 操作；使用 Redisson 提供分布式锁和请求令牌桶。
- 删除进程内缓存工具、进程内分布式锁、进程内限流实现及其调度清理线程。删除通用缓存列举、查看值、单 key 删除和全量清空入口。
- 删除课程观看权限缓存。播放、记录进度和学习心跳继续执行课程观看权限校验，但每次从权威数据计算，不依赖 Redis。
- 建立具体的 Redis 锁执行模块，不额外创建只有一个实现的抽象接口。该模块封装 key 命名、等待策略、Redisson 调用、安全释放、异常转换以及锁等待与持有时间指标；业务调用者以回调形式提交受保护操作。
- Redis 锁模块不得自行实现锁协议。只有当前线程仍持有锁时才释放；Redis 故障或获取失败时，受保护写操作明确失败，不回退到本机锁。
- API 请求限流由独立的请求限流模块管理，使用 Redisson 令牌桶，并沿用现有的可配置限流速率。配额按客户端 IP 在所有 API 实例之间共享，白名单行为保持不变。
- 学员与管理员登录失败由独立的登录失败跟踪模块管理。Lua 原子完成失败次数增加、首次设置 TTL、查询剩余 TTL 和成功后重置。
- 登录计数只表示失败的凭据验证。连续失败达到十次后锁定后续尝试；锁定窗口沿用现有业务配置：学员十分钟，管理员一小时。成功登录在尚未锁定时清除计数。
- 活跃学习租约按用户唯一。租约值至少包含学习会话标识、课程标识、课时标识和最近一次有效心跳时间。
- 学习租约 TTL 为三十秒，客户端正常心跳周期为十秒。所有时间差判断以服务端时间为准，不信任客户端提交的累计时长。
- 播放器开始播放时立即提交第一次学习心跳。第一次心跳创建学习会话和租约，但新增学习时长为零，并向客户端返回学习会话标识。
- 同一学习会话的后续心跳通过 Lua 原子验证会话归属、课时一致性、心跳顺序和连续区间，然后更新最近心跳时间与 TTL，并返回本次可累计时长。
- 心跳间隔超出允许的连续学习窗口时，本次不补算空白时长，而是重新建立时间基线。重复、过早或乱序心跳不得增加时长。
- 当另一个课时在当前租约有效期间发送心跳时，返回稳定的学习冲突业务码和当前活跃课时信息；PC 与 H5 客户端暂停冲突视频并向用户显示提示。
- 增加停止学习操作。暂停、播放结束和主动切换课时时，客户端使用学习会话标识主动停止；页面关闭时使用浏览器的尽力发送机制。只有当前租约的会话标识能够释放租约，TTL 负责处理断网和进程退出。
- 一次有效学习心跳在同一个 MySQL 事务中更新课时进度、课程进度和每日学习时长；任一权威写入失败时全部回滚。
- 在每日学习时长表上增加用户与自然日的唯一约束。迁移先按用户与自然日合并已有重复行，再创建唯一索引。
- 每日学习时长使用数据库原子 UPSERT 增加时长，不再执行“查询旧值、内存相加、按主键更新”。
- MySQL 事务提交后发布排行榜更新事件。仅 Redis 排行榜投影异步执行，权威 MySQL 写入不得放入普通异步监听器。
- 实时学习榜使用按自然日分桶的 Redis ZSet，成员为用户标识，分值为该日已确认学习时长。默认保留七天，产品查询范围仅为今天和昨天的 Top 10。
- 排行榜分值从已提交的 MySQL 时长增量更新。Redis 更新失败不得回滚 MySQL；失败应记录结构化日志和指标。
- MySQL 是学习记录和每日时长的唯一事实来源。应用启动时在投影缺失的情况下重建今天和昨天的学习榜，并提供受权限保护的手动重建操作。
- 本地演示环境不依赖 Redis 持久化保证正确性。锁、限流计数和学习租约属于短期状态，不恢复；排行榜可从 MySQL 重建。生产 Redis 高可用与持久化策略另行设计。
- 所有 Redis key 使用统一的应用命名空间，并由所属模块内部生成。Controller、Interceptor 和业务监听器不得拼接 Redis key 或直接调用通用 Redis 工具。
- 运行期间 Redis 故障时，锁、请求限流、登录失败跟踪和学习租约操作明确失败；课程权限继续查 MySQL；异步排行榜操作记录失败并等待重建。
- 本次改造应更新 PC 与 H5 的播放器心跳行为、冲突提示和停止学习行为，同时保持现有课程播放、进度展示和 Dashboard 返回结构在无必要时不变。
- 实现顺序为：Redis 基础配置与健康检查、锁执行模块、请求限流与登录失败跟踪、学习租约、MySQL 原子累计事务、实时学习榜与重建、客户端适配、测试与压测文档。

## Testing Decisions

- 测试只断言可观察行为，不断言 Redis 客户端调用次数、私有 key 构造方法或 Lua 内部步骤。
- 最高测试 seam 是学习 HTTP 接口、登录接口、全局请求限流行为和 Dashboard 查询。通过这些入口验证跨实例业务结果。
- Redis 模块以公开业务接口作为集成测试 seam，包括锁执行、请求限流、登录失败跟踪、学习租约和每日学习榜。
- 使用 Testcontainers 启动真实 Redis；不使用 Mock Redis 证明 Lua、TTL、Redisson 锁、令牌桶或 ZSet 语义。
- 增加 MySQL 集成测试，验证重复数据迁移、唯一约束、原子 UPSERT 以及课时进度、课程进度和每日时长的事务回滚。
- 验证多个并发执行者竞争同一锁时，受保护操作最多只有一个进入；非持有者不能释放锁。
- 验证 API 配额由两个应用实例共享，而不是每个实例分别拥有完整配额。
- 验证学员和管理员登录失败达到十次后锁定后续尝试、TTL 正确、成功登录清零，并验证并发失败不会丢失计数。
- 验证第一次学习心跳只建立租约且不增加时长，第二次连续有效心跳才产生增量。
- 验证同一用户、同一课时、同一学习会话能够续租；另一个课时产生明确冲突。
- 验证伪造会话、重复心跳、乱序心跳、过早心跳、超时心跳和旧标签页停止请求均不会错误增加时长或释放新租约。
- 验证主动停止后其他课时可立即建立租约，未主动停止时 TTL 到期后其他课时可以建立租约。
- 验证一次有效心跳的 MySQL 权威写入全部成功或全部回滚，Redis 排行榜失败不会反向破坏已提交事务。
- 验证同一用户同一天的并发时长增量通过原子 UPSERT 全部保留，且最终只存在一条每日统计记录。
- 验证今天和昨天的排行榜 Top 10、分值排序、少于十人、并列分值和跨自然日分桶。
- 验证清空 Redis 后可从 MySQL 重建今天与昨天的排行榜，重建操作可重复执行且结果一致。
- 验证 Redis 在启动阶段不可用时应用不进入可服务状态；运行期间故障时各模块遵循既定失败策略。
- 使用 JMeter 对两个 API 实例执行锁、限流和学习心跳场景，记录吞吐量、错误率、P95、P99 和排行榜最终一致性延迟。
- 压测报告同时保留单实例内存旧行为的基线说明与 Redis 多实例结果，重点证明正确性差异，不以未经基线测量的固定吞吐目标作为验收条件。
- 当前仓库没有可复用的自动化测试先例；本功能需要建立后端 Testcontainers 集成测试基础，并继续运行受影响前端的生产构建和 Maven 测试。

## Out of Scope

- Redis Streams、消息队列、事务 Outbox、死信队列和可靠事件重放。
- Sa-Token 会话存储、JTI 黑名单、强制下线和跨节点会话治理。
- Redis Sentinel、Redis Cluster、生产级高可用切换和 fencing token。
- Bitmap 签到、HyperLogLog 活跃统计、周榜、累计榜和任意日期范围榜单。
- 通用查询缓存、多级缓存、缓存预热以及课程观看权限缓存。
- 在 Redis 故障时自动切换为进程内锁、计数器或学习状态。
- 将 Redis 排行榜升级为权威学习数据来源。
- 完整浏览器自动化测试和生产容量承诺。

## Further Notes

- 本规格遵循 ADR-0001：Redis 是跨实例运行状态的强制依赖。
- 本规格遵循 ADR-0002：MySQL 是事实来源，Redis 每日学习榜是可重建查询投影。
- 本规格遵循 ADR-0003：同一学员只能有一个活跃学习课时。
- 预计实施周期约一周；测试与压测约占总投入的四分之一到三分之一。
- 实施中如果发现学习会话冲突需要改变产品语义，应先更新领域词汇表和 ADR，再修改实现。
