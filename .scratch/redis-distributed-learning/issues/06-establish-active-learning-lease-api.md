# 06: 建立活跃学习租约 API

**What to build:** 让学习心跳通过 Redis 原子租约确认连续学习区间，同一学员只能有一个活跃学习课时，并将有效时长同步保存为一致的 MySQL 学习事实。

**Blocked by:** 01: 建立 Redis 运行基线; 05: 原子保存权威学习数据

**Status:** ready-for-agent

- [ ] 活跃学习租约按学员唯一，并包含学习会话、课程、课时和最近有效心跳信息。
- [ ] 租约 TTL 为三十秒，正常心跳周期为十秒，所有计时以服务端时间为准。
- [ ] 第一次心跳建立租约、返回学习会话标识且新增时长为零。
- [ ] 后续心跳通过 Lua 原子验证会话归属、课时一致性和连续区间，并返回本次有效时长。
- [ ] 重复、过早、乱序和超过连续学习窗口的心跳不增加错误时长；超时心跳重新建立时间基线。
- [ ] 其他课时在租约有效期间提交心跳时返回稳定的学习冲突业务码和当前活跃课时信息。
- [ ] 提供主动停止学习操作，只有当前学习会话标识能够释放租约。
- [ ] 未主动停止时，租约到期后其他课时能够建立新的活跃学习租约。
- [ ] 有效学习时长通过 05 的事务 seam 同步保存；Redis 排行榜不在本票范围内。
- [ ] Redis 故障时心跳与停止操作返回明确可重试错误，不假装成功。
- [ ] HTTP 与 Testcontainers 集成测试覆盖正常续租、多课时冲突、伪造会话、旧会话停止和 TTL 到期。
- [ ] Maven 测试通过。
