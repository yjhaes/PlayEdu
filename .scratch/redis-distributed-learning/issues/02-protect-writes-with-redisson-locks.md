# 02: 用 Redisson 锁保护跨实例写操作

**What to build:** 让 LDAP 并发登录和学习进度写入在多个 API 实例之间真正互斥，并让调用者通过一个聚焦的锁执行模块安全运行受保护操作。

**Blocked by:** 01: 建立 Redis 运行基线

**Status:** ready-for-agent

- [ ] 建立具体的 Redis 锁执行模块，不创建只有一个实现的抽象接口，也不自行实现 Redis 锁协议。
- [ ] 锁模块统一管理 key 命名、等待策略、Redisson 调用、安全释放、异常转换和可观测信息。
- [ ] 调用者以回调形式提交受保护操作，无需自行编写获取与 finally 释放流程。
- [ ] 只有当前线程仍持有锁时才执行释放，非持有者不能释放锁。
- [ ] LDAP 登录的重复用户写入保护迁移到 Redisson，并保持原有成功和错误响应。
- [ ] 学习进度记录写入迁移到 Redisson；学习心跳暂不迁移，由 06 的学习租约替代。
- [ ] Redis 故障或锁获取失败时明确拒绝受保护写操作，不回退为本机锁。
- [ ] Testcontainers 并发测试证明多个执行者竞争同一业务锁时最多一个进入临界区。
- [ ] Maven 测试通过。
