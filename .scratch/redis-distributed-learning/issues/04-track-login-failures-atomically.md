# 04: 统一学员与管理员登录失败保护

**What to build:** 让学员和管理员登录失败次数在所有 API 实例之间原子共享，并向被锁定用户提供准确的剩余等待时间，同时保持 LDAP 登录的跨实例互斥。

**Blocked by:** 01: 建立 Redis 运行基线; 02: 用 Redisson 锁保护跨实例写操作

**Status:** ready-for-agent

- [ ] 建立独立的登录失败跟踪模块，不再复用请求限流接口。
- [ ] Lua 原子完成失败次数增加、首次设置 TTL、读取剩余 TTL 和成功登录后的重置。
- [ ] 只有凭据验证失败才增加计数，成功登录在尚未锁定时清除计数。
- [ ] 学员连续失败达到十次后锁定后续尝试，锁定窗口为十分钟。
- [ ] 管理员连续失败达到十次后锁定后续尝试，锁定窗口为一小时。
- [ ] 锁定响应显示准确且非负的剩余等待时间。
- [ ] 学员密码登录、LDAP 登录和管理员登录使用一致的阈值语义。
- [ ] LDAP 登录继续使用 02 提供的锁执行模块避免重复用户写入。
- [ ] Redis 故障时登录保护明确失败，不静默绕过安全控制。
- [ ] 并发集成测试证明失败次数不丢失，两个应用实例共享计数与 TTL。
- [ ] Maven 测试通过。
