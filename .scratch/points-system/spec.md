# PlayEdu 积分与兑换码系统

Status: ready-for-agent

## Problem Statement

PlayEdu 已有 `users.credit1` 学分字段，但当前仅在创建学员时初始化为零，并用于映射和排序；仓库中没有可信的积分发放、扣减流水、兑换商品、兑换码库存或兑换记录。直接把 `credit1` 当成完整积分系统，会使重复课程完成、并发兑换和管理员修改无法审计，也无法保证余额与兑换码交付一致。

项目需要引入面向所有未锁定学员的封闭式积分系统。学员通过首次完成课程获得积分，并使用积分兑换预先导入的外部兑换码。现有 `credit1` 复用为当前余额，但所有积分变化必须有流水，课程奖励与兑换必须在 MySQL 事务中保持一致。

## Solution

新增独立 Maven 模块 `playedu-points`，拥有积分流水、兑换商品、兑换码库存和兑换记录。`users.credit1` 作为当前可用积分余额，不新增积分账户表；新学员积分余额从零开始，每次积分变化都在同一事务中写流水并更新余额。

所有可学习课程均奖励积分。同一学员首次完成同一课程获得 10 积分，学习记录重置、重学或课程结构变化均不会重复奖励或扣回。项目尚未上线且没有业务历史数据，不提供历史奖励补发。商品售罄不暂停课程奖励。

学员通过 H5 或 PC 的积分中心查看余额、流水、兑换商品、精确库存和已交付兑换码。兑换每次只交付一枚码；余额扣减、兑换记录创建和兑换码状态变更必须原子完成。首期商品价格为 50 积分，导入 20 个兑换码；同一学员在库存允许时可重复兑换。

## User Stories

1. As a 学员, I want 首次完成任一课程获得 10 积分, so that 学习成果可以兑换外部权益。
2. As a 学员, I want 重学或学习记录被重置后不会重复获得积分, so that 奖励规则保持公平。
3. As a 学员, I want 在 H5 和 PC 查看相同的积分余额与流水, so that 两端信息一致。
4. As a 学员, I want 完成课程后立即看到获得 10 积分的提示, so that 奖励反馈清晰可感知。
5. As a 学员, I want 查看兑换商品的准确积分价格和剩余库存, so that 我能判断是否可以兑换。
6. As a 学员, I want 商品售罄后仍能继续获得永久积分, so that 奖励不受临时库存影响。
7. As a 学员, I want 兑换前看到不可取消及失效码无系统内售后的条款, so that 我能知情确认。
8. As a 学员, I want 余额足够且有库存时自动获得一枚兑换码, so that 兑换无需管理员审批。
9. As a 学员, I want 在“我的兑换”中再次查看已交付兑换码, so that 页面关闭后不会丢失权益。
10. As a 学员, I want 商品售罄时仍看到“已兑完”和零库存, so that 商品不会无故消失。
11. As a 积分超级管理员, I want 创建、下架、补货和管理兑换商品, so that 可以持续运营兑换目录。
12. As a 积分超级管理员, I want 逐行粘贴兑换码并得到新增与重复跳过报告, so that 重复导入不会制造重复库存。
13. As a 积分超级管理员, I want 删除未交付兑换码, so that 无效或不再使用的库存可被移除。
14. As a 积分超级管理员, I want 使用必填原因人工增减积分并允许负余额, so that 可以处理纠错和运营调整。
15. As a 积分超级管理员, I want 查询积分流水、兑换记录和精确库存, so that 每笔权益变化可追溯。
16. As a 学员, I want 后续奖励自动抵扣负余额, so that 账户无需独立债务模型。
17. As a 管理员, I want 删除学员时删除其全部积分和兑换关联数据, so that 学员数据不会残留。
18. As a 平台, I want 删除学员后仍保留兑换码的已发放状态且不关联个人, so that 已用外部码不会再次发给他人。
19. As a 平台, I want 并发完成和并发兑换不会重复发分、透支或重复发码, so that `credit1`、流水和库存始终一致。

## Product Decisions

### 积分经济

- 积分只归学员个人所有；讲师、管理员和部门不拥有积分账户。
- 积分只能由平台规则或超级管理员调整产生，不可购买、转让、提现或兑换现金等价物。
- 积分不会因时间经过而失效。
- 首期不提供积分排行榜。
- 兑换商品售罄后仍继续发放课程完成奖励。

### 积分获得

- 所有未锁定学员均有积分资格；部门变化不影响既有积分。
- 所有可学习课程均适用统一奖励规则。
- 同一学员、同一课程终身最多奖励一次，每次 10 积分。
- 删除或重置学习记录不扣回积分；再次完成也不重复奖励。

### 余额与人工调整

- 使用现有 `users.credit1` 保存当前可用积分，不新建积分账户表。
- 新学员余额使用默认零值；不执行历史积分清零或迁移。
- 所有获得、兑换和人工调整都产生积分流水；账户存续期间流水不可修改或删除。
- 只有现有超级管理员能够执行积分运营操作。
- 人工调整提交非零正负变更值和必填自由文本原因，不使用原因分类。
- 只有人工扣分允许余额变为负数；兑换永远不能透支。
- 新奖励直接与负余额相加；积分中心以普通负数形式展示，不额外弹窗。
- 人工调整只在积分流水中可见，不额外向学员推送。

### 兑换商品与兑换码

- 首期只有一个试运行商品，价格为 50 积分，初始导入 20 个兑换码。
- 每个商品独立定价；商品一旦发放过兑换码，价格不可修改，变价需创建新商品。
- 商品只要求名称和积分价格，不要求图片或商品级使用说明。
- 商品可下架；下架停止新兑换，但保留库存和历史。
- 商品售罄后继续显示并标记“已兑完”，同时显示精确剩余库存。
- 同一商品可补货且维持原价；同一学员可重复兑换。
- 每次兑换只交付一枚兑换码，不支持购物车或批量兑换。
- 兑换前确认商品、价格、不可取消和“失效码不提供系统内售后”。
- 已交付兑换不可取消；首期不记录兑换码有效期，也不提供失效码补发或退分。
- 兑换码通过后台多行文本框逐行粘贴；不保存导入批次或采购参考字段。
- 重复兑换码跳过并在当次导入报告中展示；导入报告不作为永久批次实体保存。
- 未交付兑换码可直接物理删除，不保留撤销状态。
- 兑换码导入后永久绑定一个商品，不得转移。
- 从未发放过兑换码的商品可连同全部未交付码物理删除；存在已发放码时只能下架。
- 兑换码加密保存；超级管理员查看明文不增加独立查看审计，只记录导入等变更操作。

### 学员端与数据生命周期

- H5 和 PC 均提供独立积分中心：余额、流水、商品、精确库存和我的兑换。
- 新课程奖励立即提示“获得 10 积分”并可跳转积分中心。
- 积分中心提供长期规则说明，兑换确认框再次展示关键条款。
- `is_lock = 1` 沿用现有前台访问控制并阻止兑换；`is_active` 不新增积分语义。
- 锁定期间保留余额、流水和已交付兑换；解锁后恢复访问。
- 删除学员时物理删除其积分流水和兑换记录，并随用户行删除 `credit1`；不匿名化保留用户审计。
- 兑换码表不直接存 `user_id`。删除学员后，已交付码仍保留已发放状态，但无法反查原学员。

## Architecture and Module Boundaries

- 新增 `playedu-points` Maven 模块，依赖 `playedu-common`；运行模块 `playedu-api` 依赖该模块。
- 积分领域拥有积分流水、商品、兑换码和兑换记录。`playedu-common` 继续拥有 `User` 和 `credit1`。
- HTTP Controller 和请求 DTO 位于运行模块 `playedu-api`；积分业务规则位于 `playedu-points`。
- `playedu-course` 在首次课程完成跃迁中调用明确的积分奖励入口。奖励写入与学习事实使用同一个 Spring/MySQL 事务。
- 不使用 Redis 保存积分余额、库存或兑换状态；MySQL 是全部积分和兑换事实来源。
- 不使用现有异步每日学习榜事件发放积分，也不引入消息队列、Outbox 或异步补偿。
- 学员删除由跨模块事务门面协调，确保用户、学习关联、积分流水和兑换记录不会部分删除。已发放兑换码状态不参与删除。

## Data Model

### `users.credit1`

- 作为当前可用积分余额，使用有符号整数。
- 新学员使用默认零值。
- 只允许积分领域服务更新；Controller、课程服务和管理员服务不得直接设置绝对余额。
- 获得和人工调整使用原子加减；兑换使用余额充足条件更新，避免并发透支。

### `point_ledgers`

- `id`
- `user_id`
- `delta`：有符号积分变化
- `balance_after`：本次变化后的余额快照
- `type`：`COURSE_COMPLETION`、`REDEMPTION`、`MANUAL_ADJUSTMENT`
- `source_key`：全局唯一幂等键
- `reason`：仅人工调整必填
- `operator_admin_id`：仅人工调整填写
- `created_at`
- 建立 `(user_id, created_at, id)` 查询索引和 `source_key` 唯一约束。

课程奖励的 `source_key` 使用稳定的学员与课程自然键。重复完成和重学使用相同幂等键，避免重复发放。

### `point_products`

- `id`
- `name`
- `points_price`：正整数
- `status`：`ON_SALE`、`OFF_SALE`
- `created_at`、`updated_at`

价格是否可修改由“是否存在已发放兑换码”判断。商品删除前必须不存在 `DELIVERED` 兑换码；删除时同步删除全部未交付码。

### `point_codes`

- `id`
- `product_id`
- `code_ciphertext`：可解密的兑换码密文
- `code_digest`：规范化兑换码的带密钥摘要，用于唯一约束和重复导入检查
- `status`：仅 `AVAILABLE`、`DELIVERED`
- `delivered_at`
- `created_at`、`updated_at`

兑换码表不包含 `user_id`、批次、有效期或撤销字段。使用专用外部密钥进行带认证加密，并使用独立或派生的 HMAC 摘要；不得复用 JWT 密钥或记录兑换码明文。

### `point_redemptions`

- `id`
- `user_id`
- `product_id`
- `code_id`：唯一，一枚兑换码最多对应一次兑换
- `points_cost`：兑换时价格快照
- `created_at`

兑换记录是学员与兑换码之间的唯一关联。删除学员时物理删除对应记录；`point_codes` 中的 `DELIVERED` 状态保持不变。

## Core Transactions

### 首次课程完成奖励

1. 服务端确认课程完成状态发生 `未完成 → 已完成` 跃迁。
2. 在现有学习事实事务中尝试插入唯一课程奖励流水。
3. 仅当流水实际插入时，执行 `credit1 = credit1 + 10` 并保存 `balance_after`。
4. 任一步失败时，学习完成事实、流水和余额全部回滚。
5. 返回本次实际获得积分，供 PC/H5 展示即时提示。

### 兑换

1. 校验学员未锁定、商品在售且积分价格有效。
2. 锁定或原子领取一枚 `AVAILABLE` 兑换码。
3. 以 `credit1 >= points_price` 为条件原子扣减余额；不允许兑换产生负余额。
4. 将兑换码改为 `DELIVERED`，记录 `delivered_at`。
5. 创建兑换记录和 `REDEMPTION` 流水，保存价格与余额快照。
6. 在同一事务提交；缺库存、余额不足、重复请求或任一写入失败时全部回滚。
7. 接口使用客户端幂等键或稳定请求键，防止网络重试重复扣分或发码。

### 人工调整

1. 校验当前管理员为现有超级管理员。
2. 校验变更值非零、自由文本原因非空。
3. 原子更新 `credit1`；人工扣分允许产生负余额。
4. 同事务写 `MANUAL_ADJUSTMENT` 流水、操作者和余额快照。

### 学员删除

1. 在跨模块事务中删除学员的积分流水和兑换记录。
2. 保留对应兑换码的 `DELIVERED` 状态，兑换码不含用户关联。
3. 继续执行现有学习、部门和登录数据清理，再物理删除用户。
4. 任一清理失败时整个删除事务回滚，避免孤立部分数据。

## API Surfaces

### 学员 API

- 积分摘要：仅返回当前可用余额 `credit1`，不包含历史补发提示状态。
- 积分流水分页：类型、变化值、原因、时间、余额快照。
- 兑换商品列表与详情：名称、价格、上下架状态、精确可用库存。
- 兑换操作：要求幂等键，返回已交付兑换记录。
- 我的兑换分页与详情：仅本人可访问，详情按需解密兑换码。
- 积分规则：两端使用同一规则内容。

### 后台 API

- 学员积分调整。
- 积分流水、兑换记录和商品库存的搜索分页。
- 商品创建、修改、上下架、补货和受约束删除。
- 多行兑换码导入、重复跳过报告和未交付码删除。
- 已交付兑换码按需解密查看。
- 所有写操作以及导入使用现有后台日志能力；不新增明文查看专用日志。
- 所有积分后台 API 除认证外必须显式校验 `BackendBus.isSuperAdmin()`。

## Rollout

1. 创建积分领域表、索引和唯一约束，验证兑换码加密密钥配置。
2. 新学员积分余额从零开始，不执行历史清零、补发或迁移闸门确认。
3. 超级管理员创建试运行商品，设置价格 50，并逐行导入 20 个兑换码。
4. 验证首次完成奖励、余额、流水、库存和兑换记录，以及 H5/PC 积分中心。
5. 上线后观察重复导入、奖励幂等、兑换失败、余额与流水差异以及库存变化。

## Testing Decisions

- 后端单元测试覆盖积分变更、负余额、商品状态和码状态规则。
- MySQL 集成测试覆盖 `credit1` 与流水同事务提交、回滚和并发更新。
- 验证课程完成奖励与学习事实同时提交；任一写入失败时全部回滚。
- 验证同一学员同一课程的并发完成只奖励一次；重置和重学不重复奖励。
- 验证兑换并发时余额不透支、一枚码只发一次、精确库存不为负。
- 验证重复客户端请求返回同一兑换结果，不重复扣分或发码。
- 验证人工扣分可产生负余额，后续课程奖励正确抵扣，兑换仍禁止透支。
- 验证兑换码密文不出现在日志、数据库错误和导入报告中；重复摘要被跳过。
- 验证普通管理员无法调用任何积分运营 API；超级管理员可调用。
- 验证商品补货、售罄展示、下架和受约束删除；有已发放码的商品不可物理删除。
- 验证删除学员会删除余额主体、积分流水和兑换记录，但已发放兑换码状态仍保留且无用户关联。
- 验证锁定学员无法访问积分 API，解锁后余额与兑换记录恢复可见。
- 运行 Maven 测试、`playedu-admin`、`playedu-pc` 和 `playedu-h5` 生产构建。

## Out of Scope

- 旧积分清零、历史课程奖励补发、迁移状态闸门及历史补发提示。
- 积分购买、转让、提现、现金兑换或部门积分池。
- 积分过期、活动积分和积分排行榜。
- 考试、签到、登录、学习时长或课时完成奖励。
- 课程兑换、实物商品、第三方供应商 API、欠货订单和候补队列。
- 一次兑换多枚码、购物车、兑换取消、退分、补码或失效码售后。
- 兑换码有效期、采购批次、商品图片和商品级富文本说明。
- 兑换码转商品、已交付码删除或再次发放。
- 普通管理员积分权限、审批流、双人复核和明文查看专用审计。
- 积分汇总看板、CSV 导出、邮件或外部推送。
- Redis 积分余额、异步奖励、消息队列和事务 Outbox。

## Further Notes

- 领域词汇见根目录 `CONTEXT.md`。
- 关键决策见 ADR-0004 至 ADR-0022；已标记 superseded 的 ADR 只保留决策历史，不代表当前方案。
- 当前课程完成服务只暴露最终状态，实施时必须显式识别 `未完成 → 已完成` 跃迁，并以数据库唯一幂等键作为最后防线。
- 当前用户删除流程不是统一事务，实施时必须先建立删除事务门面，再接入积分清理。
- 首期虽只有 20 个兑换码，但所有学员都会持续积累永久积分；补货与新增商品是持续运营责任。
