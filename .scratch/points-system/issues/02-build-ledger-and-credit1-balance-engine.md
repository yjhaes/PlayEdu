# 02: 建立积分流水与 credit1 余额引擎

**What to build:** 让积分领域成为 `users.credit1` 的唯一写入入口，并以同事务流水实现课程奖励、兑换扣分和人工调整所需的原子余额变化。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 不创建积分账户表，`users.credit1` 明确作为当前可用积分余额。
- [ ] 提供基于非零 `delta`、类型、唯一 `source_key` 的积分变更入口。
- [ ] 每次积分变化在同一事务内更新 `credit1` 并插入包含 `balance_after` 的流水。
- [ ] 重复 `source_key` 返回原结果，不重复更新余额。
- [ ] 普通奖励和兑换不能产生负余额；人工扣分可产生负余额。
- [ ] 人工调整要求自由文本原因和超级管理员标识，并保留操作者 ID。
- [ ] 后续正向奖励能自然抵扣负余额。
- [ ] 禁止 Controller 或其他领域直接设置 `credit1` 绝对值。
- [ ] 集成测试覆盖提交、回滚、重复请求、并发加减和负余额。
