从请求地址找到后端方法

8～10 分钟 · 第一课 · 不依赖应用已启动

本课的一个收获：看到课程详情请求，就能找出处理方法、传入的课程编号，以及下一步该跟的业务调用。这是面试讲解请求链的起点。

1. 只看这几行

摘自当前项目 CourseController.java 第 37～60 行，省略无关字段、注解和后续方法体。它是学员端课程接口。

@RestController
@RequestMapping("/api/v1/course")
public class CourseController {
    // 省略字段
    @GetMapping("/{id}")
    public JsonResponse detail(@PathVariable(name = "id") Integer id) {
        Course course = courseService.findOrFail(id);
        // 省略后续响应组装
    }
}

这个片段用于阅读，不是可独立编译的完整类。

代码线索本课只记这一件事
@RequestMapping类上给出公共路径 /api/v1/course。
@GetMapping方法上指定 GET 请求和剩余路径 /{id}。
@PathVariable把路径中的 id 绑定到 Java 参数 id，并转换为 Integer。

以上基础规则见 Spring 官方请求映射文档。这里只讨论映射；真实请求仍需经过相关拦截器等处理，课程是否存在也要由业务代码判断。

2. 看懂一个例子

假设请求是 GET /api/v1/course/7：

公共路径 /api/v1/course + 方法路径 /{id}
                  ↓ 用 7 替换 id
CourseController.detail，参数 id = 7
                  ↓ 方法体的第一步
courseService.findOrFail(7)

请求路径不包含 Java 方法名 detail。方法名和对外 URL 可以不同。上面只是定位和传参结果，不保证课程 7 存在，也不保证请求已通过访问检查。

3. 换一个编号，自己判断

先尽量不回看例子。输入答案后立即获得反馈；答案不会发送给助手或保存到服务器。

4. 关闭例子后，做一次迁移

在聊天里回答：如果只把类上的公共路径改成 /api/v2/course，编号 19 的课程对应什么请求？Java 方法名需要跟着改变吗？说明原因。

如果不知道 GET、Java 参数或注解是什么意思，直接告诉助手卡在哪一步。无需猜，也无需一次学完所有 Spring 原理。
