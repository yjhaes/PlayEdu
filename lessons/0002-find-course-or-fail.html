查到课程，或抛出异常

8～10 分钟 · 沿课程详情请求继续 · 无需应用已启动

本课目标：读懂一个真实 Service 方法的两条执行分支，解释它何时返回课程、何时中断正常执行。

1. 从调用找到实现

课程详情 Controller 调用 courseService.findOrFail(id)。CourseService 接口声明操作；下面的实现位于 CourseServiceImpl 第 174～179 行。

public Course findOrFail(Integer id) throws NotFoundException {
    Course course = getOne(query().getWrapper().eq("id", id));
    if (course == null) {
        throw new NotFoundException("课程不存在");
    }
    return course;
}

接口告诉调用方“有哪些操作”，实现提供具体执行代码。本课先沿这段方法体阅读，依赖注入的详细规则留到后续。

2. 查询这一行做了什么？

Course course = getOne(query().getWrapper().eq("id", id));

query().getWrapper() 提供查询条件对象；eq("id", id) 加入“数据库 id 列等于方法参数 id”的条件。引号内的 "id" 是列名，引号外的 id 是这次请求的参数值。

getOne 是 MyBatis-Plus 提供的查询单个实体的操作，不是 Java 自带的方法。找到课程后，把课程对象赋给变量 course；无匹配记录时为 null。相关用法见 官方 getOne 说明及条件构造器说明。

Course 通过 TableName 映射到 courses 表，id 是主键。若参数是 10，查询意图可用下面的 SQL 理解：

-- 教学用示意 SQL，不是已捕获的实际 SQL 日志
SELECT * FROM courses WHERE id = 10;

框架实际使用参数绑定和实体字段映射；不能把示意 SQL 当作源码里存在的一条手写语句。当前实现继承 ServiceImpl，CourseMapper 继承 BaseMapper，因此基础查询无需为这个方法另写一条 XML SQL。

3. 接着看两条分支

查询结果接下来执行什么
找到课程对象course == null 不成立，执行 return course，返回给 Controller。
没有匹配记录course == null 成立，执行 throw 抛出“课程不存在”异常，本次调用不会正常返回课程。

throws NotFoundException 是方法声明，提示这个方法可能抛出异常；throw new NotFoundException(...) 是真正抛异常的执行语句。不是每次进入方法都会抛异常。

异常对应的客户端响应由后续异常处理流程决定，本课暂不判断 HTTP 状态码。这个方法检查课程是否存在，不等于完成访问权限检查。

5. 用自己的话解释

在聊天中回答：假设课程 10 存在、课程 99 不存在，分别调用 findOrFail(10) 和 findOrFail(99)，会发生什么？不要只说“成功”和“失败”，说出查询结果和后续分支。

如果 getOne、null、return 或 throw 不熟，直接告诉助手是哪一个。下一次复习先回忆两条分支，再继续看 Controller 如何组装响应。
